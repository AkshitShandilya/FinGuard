# FinGuard AI

### Real-Time Financial Fraud Detection System

FinGuard AI is a real-time financial fraud detection system that combines deterministic rules, supervised machine learning, unsupervised anomaly detection, and behavioral analysis to identify potentially fraudulent transactions.

The system generates an explainable risk score for every transaction and provides analysts with the evidence behind each decision, enabling faster investigation and continuous improvement through analyst feedback.

## Overview

Traditional fraud detection systems often rely heavily on static, hand-written rules. While these rules can detect known fraud patterns, they can struggle with new attack patterns and may generate a large number of false positives.

FinGuard AI addresses this by combining multiple detection approaches in a single real-time scoring pipeline:

- Deterministic rule-based detection
- Supervised fraud classification
- Unsupervised anomaly detection
- Behavioral analysis
- Explainable AI

The resulting signals are aggregated into a single **Final Risk Score from 0 to 100**.

---

## Problem Statement

Financial institutions process large volumes of transactions every day, making real-time fraud detection increasingly important.

Legacy rule-based systems can face several limitations:

- Novel fraud patterns may not be covered by existing rules.
- Fixed thresholds can result in excessive false positives.
- Batch processing can introduce detection delays.
- Analysts may need to manually collect evidence for each case.
- Some systems provide limited explanations for their decisions.

FinGuard AI aims to provide a more adaptive and explainable approach to transaction fraud detection.

---

## Objectives

The main objectives of FinGuard AI are:

1. Build a real-time transaction risk-scoring engine.
2. Combine deterministic rules with supervised and unsupervised machine learning.
3. Detect both known fraud patterns and behavioral anomalies.
4. Generate explainable decisions using SHAP.
5. Automate evidence assembly for analyst investigation.
6. Support continuous model improvement through analyst feedback.

Detection Pipeline
1. Transaction Ingestion

Transactions enter the system through the API Gateway.

The gateway provides:

JWT authentication
Role-Based Access Control (RBAC)
2. Feature Extraction

Relevant transaction and behavioral features are extracted before the detection stage.

Key features include:

Transaction amount
Transaction velocity
Geographic deviation
Device fingerprint
Account history
Other behavioral signals
3. Parallel Detection

The transaction is evaluated using three complementary detection mechanisms.

Rule Engine

Deterministic rules identify known suspicious patterns using predefined conditions.

XGBoost

A supervised machine-learning model performs transaction-level fraud classification using historical transaction data.

Isolation Forest

An unsupervised anomaly-detection model identifies transactions that deviate significantly from normal behavioral patterns.

4. Risk Aggregation

The signals generated by the detection components are combined into a single:

Final Risk Score: 0–100

5. Decision

The final score determines the appropriate action for the transaction.

6. Analyst Review

Flagged transactions are displayed on the analyst dashboard along with their supporting evidence and explanations.

7. Feedback Loop

Analyst decisions such as confirmed fraud or false positive are stored in the feedback database and can be used for future model improvement and retraining.

Risk Scoring

FinGuard AI uses four risk tiers:

Risk Score	Risk Level	Action
0–30	Low	Approve
31–60	Medium	Hold + Verify
61–80	High	Hold + Alert
81–100	Critical	Block + Open Case
Explainability

FinGuard AI uses SHAP (SHapley Additive exPlanations) to provide feature-level explanations for individual predictions.

Instead of displaying only a fraud probability or risk score, the system identifies the features that contributed to the decision.

Example contributing factors may include:

Unusually high transaction amount
Unrecognized device
Unusual geographic location
High transaction velocity
Account history

This allows analysts to understand why a transaction received a particular risk score.

Evaluation Metrics

The system will be evaluated using the following KPIs:

Fraud Recall

Measures the proportion of actual fraudulent transactions correctly detected by the system.

False Positive Rate

Measures the proportion of legitimate transactions incorrectly flagged as suspicious.

Mean Time to Detect

Measures the time between a transaction occurring and its risk score being generated.

Analyst Productivity

Measures the change in average case-investigation time when using the analyst dashboard compared with manual investigation.

Fraud Loss Avoided

Measures the estimated monetary value of fraud prevented during the evaluation period.
